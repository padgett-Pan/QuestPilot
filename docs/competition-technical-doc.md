## 摘要

QuestPilot（竞途智策）是一款服务高校竞赛团队的 AI 学习与协作 Web 应用。学生在同一工作区维护竞赛目标、计划任务、参考资料与作品评审；教师可以查看团队成员、提交邀请并留下批注。产品设计以“目标诊断—计划拆解—资料依据—作品反馈—团队行动”为连续流程，避免 AI 输出停留在一次性聊天。

当前可运行版本使用 Next.js 16、React 19 与 TypeScript。登录、注册、页面访问控制与业务 API session 校验均已实现：`proxy.ts` 拦截八个工作区路由，`/dashboard` 在服务端二次校验 session 有效性，密码使用 scrypt + 每用户随机盐并以常量时间比较，session 带 7 天过期时间。计划、资料、媒体任务、评审与团队数据由本地 JSON 运行时存储维护。资料问答采用段落切块 + TF-IDF + 余弦相似度的片段级检索，返回命中片段、相似度分数与字符区间；配置文本模型后可基于检索片段作答。作品评审分数由项目真实状态计算或由模型按维度打分，每个分数附带证据说明。每个账号注册后自动获得独立工作区，计划、资料、媒体与评审按团队隔离，跨工作区请求一律返回 404；17 条自动化测试覆盖检索、评分、密码哈希与工作区隔离。PostgreSQL、MinIO、Prisma 与 Worker 配置已随源代码提供，但当前 Web 运行链路尚未切换到这些服务；音视频转写与视觉分析仍未接入。

## 1. 项目概述

### 1.1 赛项背景与目标

本项目选择自拟方向“AI 教育与学习平台”，聚焦三人竞赛团队在备赛过程中目标不清、资料分散、任务协作脱节、评审意见难转为行动等问题。QuestPilot 将赛事评分要求转化为工作区信息结构和任务提醒，使学生明确下一步、教师能够查看推进状态。

产品不是通用问答机器人。核心体验由可保存的计划、任务、资料条目、作品评审记录和教师批注组成；AI 计划生成用于把自然语言目标转为阶段任务，其他 AI 能力在本地演示模式下用有明确标识的样例结果展示。

### 1.2 目标用户

| 用户 | 主要目标 | 使用模块 |
|---|---|---|
| 学生 | 把竞赛目标拆解为任务，掌握资料和评审意见 | 工作台、计划画布、知识库、作品评审、教师批注 |
| 指导教师 | 查看团队进度、提供反馈并邀请成员 | 团队协作、教师批注、计划与评审查看 |
| 评审人员 | 快速理解产品价值、AI 流程和工程边界 | 首页、演示账号、技术文档、录制演示 |

### 1.3 设计原则

1. AI 输出连接到可跟踪计划或证据，不把聊天作为唯一成果。
2. 演示模式和真实模型模式有明确状态提示，不把演示结果描述成真实推理。
3. 比赛评分维度进入产品文案、评审维度和技术文档。
4. 用户数据和服务密钥不进入公共代码包；本地演示数据与生产存储明确区分。

### 1.4 官方提交约束

2026-10-18 刷新查询博学谷官方赛道详情接口：赛道要求每队不超过 3 名学生，本队按三人团队规划；省赛报名和作品提交截止日期为 **2026-11-18**，仍需以学校通知为准，校内截止可能更早。官方要求提交 GitHub/Gitee 公共或可评审代码仓库、清晰代码结构与 README、完整 Git 历史、环境变量模板和依赖说明；另需 5–8 分钟普通话演示视频及不超过 30 页的 PDF 技术文档。该项目当前保持本地 Git，不创建 GitHub/Gitee 远程仓库；提交前团队需按赛事要求另行发布评审可访问仓库。

PDF 技术文档覆盖项目概述、需求、架构、AI 方案、核心功能、测试部署、总结展望。视频稿覆盖项目介绍、核心功能和 AI 技术亮点，并标记演示结果来源。

## 3. 系统架构

### 3.1 当前可运行架构

```text
浏览器
  ├─ Next.js App Router 页面（Server / Client Components）
  ├─ proxy.ts：工作区路由的 cookie 快速检查
  └─ Route Handlers（requireApiUser 校验 session）
       ├─ 注册、登录、退出
       ├─ 计划、知识、媒体、评审、团队 API
       ├─ OpenAI 兼容文本模型适配（可选，45s 超时 + 429/5xx 重试一次）
       ├─ 检索层：段落切块 + TF-IDF + 余弦相似度
       └─ 评分层：证据驱动评审（任务/资料/媒体/反馈）
              ↓
       本地运行时状态：data/runtime-store.json（按 teamId 隔离）
```

Next.js Proxy 对工作区页面执行快速 cookie 存在性检查；业务 API 使用 `requireApiUser` 查询本地 session，无效会话返回 HTTP 401。Proxy 只负责页面跳转，API 在处理器内独立校验 session。

### 3.2 部署骨架与当前边界

项目保留 Prisma schema、PostgreSQL + pgvector Docker Compose 配置、MinIO 配置和 Worker 入口。它们是后续部署目标，不代表当前 Web 运行链路已接入。当前 Worker 只启动并周期输出轮询提示，没有数据库任务锁、任务领取、FFmpeg 调度或重试实现。Docker Compose 中 app/worker 的生产链路尚未完成联调。

### 3.3 主要目录

| 目录 | 职责 |
|---|---|
| `app/` | 页面与 Route Handlers |
| `components/` | 工作区导航、动效和通用界面组件 |
| `lib/` | AI 适配、检索、评审评分、认证辅助与本地运行时存储 |

## 4. AI 技术方案

### 4.1 AI 计划生成

计划输入包含竞赛目标、团队概况和技能描述。文本模型由 `AI_BASE_URL`、`AI_API_KEY`、`AI_TEXT_MODEL` 配置，采用 OpenAI 兼容 Chat Completions 请求。模型响应经 Zod schema 校验，转换为阶段、任务、负责人、优先级和风险后保存到本地运行时存储。未配置模型或输出结构不符合 schema 时，返回固定 DemoProvider 计划。

接入成本被压到改三行环境变量：`lib/ai.ts` 内置 DeepSeek、阿里百炼、智谱 GLM、Moonshot、OpenAI 五个兼容端点预设，换供应商只需改 `AI_BASE_URL` 与 `AI_TEXT_MODEL`，不需要改代码。请求超时 45 秒；429 与 5xx 自动重试一次，4xx（密钥或模型名错误）不重试，直接把错误交给上层标注为 `fallback-error`。

`GET /api/ai/status` 返回是否接通、供应商、模型名和掩码后的密钥片段；工作台顶部的状态徽标据此显示“真实模型”或“演示模式”，评委不需要翻文档就能判断结果来源。

当前实现了结构化计划生成与 fallback；没有实现自主工具调用、Agent 多步规划、MCP 连接或自动检索工具。录制时应展示“计划生成 + schema 校验 + fallback”，不能声称已有多 Agent/MCP。

### 4.2 资料问答与引用

知识库接受 TXT/Markdown 文件并记录网页链接。上传时按空行分段切块（超长段落按 320 字滑动、60 字重叠），记录每块的字符区间，片段数由真实切块结果得出，不再按字数估算。

检索链路（`lib/retrieval.ts`）：中文按二元组、英文与数字按整词切分 → 统计片段级文档频率 → 以平滑 IDF 计算 TF-IDF 权重 → 查询与片段分别计算加权向量并取余弦相似度 → 返回 top-3 命中片段及分数。问答接口把命中片段拼成带编号的上下文：配置文本模型时由模型在“只能依据片段作答、逐条标注 [编号]”的约束下生成回答；未配置时返回摘录式回答。两种路径都会返回真实的片段标题、片段序号、相似度分数与字符区间。

已验证的行为：不同问题命中不同片段（例如“AI 技术深度”命中评分标准块，“提交截止时间”命中时间线块），域外问题返回 0 命中并明确提示。

尚未实现：embedding 语义召回、向量库持久化、查询改写与重排、PDF 与网页正文解析。词法检索对同义改写不敏感，这是当前方案的已知上限，不能与 embedding 检索混称。

后续 RAG 方案：解析 PDF/网页；按章节切分并记录页码或 URL 锚点；生成 embedding 并写入 pgvector；按问题检索 top-k 片段；引用回到原文；记录检索命中率与回答无依据率。

### 4.3 音视频作品评审

上传接口检查 MIME 类型与 200 MB 大小上限后，把文件真实写入 `uploads/` 目录（已加入 `.gitignore`），并记录 `storageKey`。分析接口读取真实文件字节数并推进任务状态（QUEUED → PROCESSING → COMPLETED / FAILED）；文件缺失时返回 422 与失败状态。

诚实边界：当前没有接入 FFmpeg 抽帧、语音转写与视觉模型，因此分析结果不产出转写文本，`transcript` 为 `null`、`frames` 为 0，并显式返回 `isSample: true` 与说明文案；建议列表是按评分维度给出的样例，不代表对文件内容的理解。

真实流程应依次完成安全存储、媒体探测、音轨提取、转写、视频关键帧抽取、视觉分析、评分维度结构化输出、任务状态持久化和临时文件清理。完成联调后才能标为真实多模态评审。

### 4.5 AI 能力落地情况总览

| 能力 | 是否落地 | 使用方式 | 代码位置 |
|---|---|---|---|
| 结构化计划生成 | 已落地 | 计划页输入目标触发；配置模型后为真实推理，未配置为可复现演示 | `app/api/plans/generate/route.ts` |
| 片段级检索问答 | 已落地（词法） | 知识库上传 TXT/Markdown 后提问，返回命中片段与分数 | `lib/retrieval.ts`、`app/api/knowledge/query/route.ts` |

| 证据驱动评审 | 已落地 | 评审页生成；无模型时按项目状态计算，有模型时按维度打分 | `lib/review.ts` |

### 4.4 安全与可控

- API key 只通过环境变量读取，`.env.local` 被 `.gitignore` 忽略。
- 计划输出经 Zod schema 验证；解析失败时回退 DemoProvider。
- 页面使用 HTTP-only、SameSite=Lax session cookie；生产模式设置 Secure。
- 服务端 session 记录 `expiresAt`，7 天到期后自动失效并被清理；退出登录会同时删除服务端 token。
- 密码使用 scrypt + 每用户独立随机盐，比较时使用 `crypto.timingSafeEqual`；登录时账号不存在也执行一次等价开销的哈希，避免通过响应时间枚举账号。
- `proxy.ts` 拦截八个工作区路由做 cookie 存在性快速判断（Edge 运行时无法读文件）；`/dashboard` 在服务端用 `getCurrentUser()` 做真实校验并重定向，业务 API 用 `requireApiUser()` 校验，无效/过期 session 返回 401。
- 本地 JSON store 是单机演示方案：工作区隔离在应用层按 `teamId` 过滤，但没有数据库级行级权限、并发写入控制、审计与密钥轮换，不适合作为公开生产数据存储。

## 5. 核心功能

### 5.1 首页与评分标准映射

首页说明目标用户、产品能力和官方评分维度，并提供登录/注册和工作台入口。登录后的用户直接进入工作区；未登录访问工作区页面会被引导至登录页。

### 5.2 工作台与计划画布

工作台汇总当前工作区的计划任务、准备度指标、评审建议、团队和资料条目。计划画布调用计划生成/重规划 API，将结果转成可保存任务。准备度评分与「生成评审」走同一套公式，随任务完成状态变化，不是写死的静态分数；它反映项目准备度，不等同于评委打分。

### 5.3 知识库

支持上传 TXT/Markdown 文件（单份上限 10 MB），按段落切块后进入检索索引；也支持记录 HTTP/HTTPS 网页链接（仅记录条目）。问答返回命中片段列表，每条包含资料标题、片段序号、相似度分数与字符区间。网页正文抓取与 PDF 内容提取尚未实现。

### 5.4 作品评审

支持 MP3、WAV、MP4、WebM 上传校验，最大 200 MB，文件写入本地 `uploads/`。评审分数不再固定：由任务进度、资料片段数、媒体任务完成数、团队反馈计算，或在配置模型后由模型按六个维度打分，每个维度附证据说明。转写与关键帧分析需接入 FFmpeg 与相应模型后才能启用。

### 5.5 团队与教师批注

团队页展示当前工作区成员，支持写入邀请记录（同一邮箱不可重复邀请）；批注 API 保存文本、作者与时间。改团队名需要“指导教师”或工作区所有者身份。注册新账号会创建独立工作区，只带一份评分标准摘要作为起步资料，因此两个账号登录看到的是彼此不可见的数据。邀请目前只落库、不发邮件，也不自动授予访问权限。

## 6. 评分标准对照与实现状态

官网 2026 赛项详情列出的一级权重为 AI 技术深度 35%、创新性 25%、前端工程质量 10%、实用性 10%、用户体验 10%、社会意义与商业前景 10%。

AI 技术深度 35% 的细分考察点为：大模型集成质量 8%、Agent/工作流设计 8%、RAG 检索增强 6%、多模态能力 5%、AI 安全与可控性 4%、MCP/函数调用集成 4%。本项目逐项对应如下，每一项都能指到具体文件与接口：

- **大模型集成（8%）**：计划生成、检索受限作答、维度评分三处走同一 OpenAI 兼容适配器，输出经 Zod 校验，来源分为 `live / fallback-schema / fallback-error / demo` 四态并在界面显示，`/api/ai/status` 暴露当前模型。
- **RAG（6%）**：自建切块与 TF-IDF 余弦检索，返回片段、相似度与字符区间，问答强制基于片段作答并标注编号；未使用 embedding，词法检索对同义改写不敏感是已知上限。
- **AI 安全与可控（4%）**：scrypt + 每用户盐、恒定时间比较、7 天 session、页面与 API 双重校验；模型失败时不伪造结果，直接标注回退来源。
- **多模态（5%）与 Agent/MCP（4%）**：仅预留接口与部署骨架，代码未实现，本文不按已实现计分。

## 7. 数据与安全

本地演示数据存储在 `data/runtime-store.json`，该目录已被 Git 忽略且不进入交付包。知识上传文本进入该文件；音视频文件写入 `uploads/`（同样被 Git 忽略），store 中只保存文件名、大小、状态与 `storageKey`。所有业务记录都带 `teamId`，`getWorkspace(user)` 是唯一的数据入口，读写都按当前账号的工作区过滤。

密码使用 scrypt + 每用户随机盐存储；session 记录过期时间，退出登录同时删除服务端 token。

- 交付包不包含 `.env.local`、AI/SMTP 密钥、本地数据、上传文件、日志和临时目录。
- `.env.example` 只含占位配置。
- 公开部署前应更换 session 实现、配置强 `SESSION_SECRET`、启用 HTTPS，并配置数据库级权限与用户/团队隔离。
- 邀请 API 目前仅记录邮箱；不发送邮件，也不自动授予受邀账户访问权限。

## 9. 本地运行与部署

### 9.1 环境要求

Windows 10/11、Node.js 22（实测 22.22.2）、pnpm 12（实测 12.15.0）。Docker Desktop、FFmpeg 为部署目标的可选依赖；纯演示模式不要求启动 PostgreSQL 或 MinIO。可选配置 OpenAI 兼容文本模型用于计划生成。

### 9.2 演示模式

```powershell
pnpm install
Copy-Item .env.example .env.local
pnpm dev
```

访问 `http://localhost:3000`。学生演示账号：`student@questpilot.local` / `demo-student-password`；教师演示账号：`teacher@questpilot.local` / `demo-teacher-password`。仅用于本地演示，不可用于公开生产服务。

### 9.3 真实文本模型

在 `.env.local` 设置 `AI_BASE_URL`、`AI_API_KEY` 和 `AI_TEXT_MODEL` 后重启服务。API key 不得写入源代码、README、录屏、截图或提交包。其他模型环境变量目前是预留配置，不代表视觉、Embedding 或转写已接通。

### 9.4 数据库部署目标

项目提供 `docker-compose.yml` 和 Prisma schema，但数据库接入尚未完成。启动 compose 只会启动定义的基础设施，不能据此推断应用已经使用 PostgreSQL/MinIO。生产部署前需完成 schema migration、健康检查、数据迁移和回滚演练。
